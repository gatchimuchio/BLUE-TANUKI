## 2. 決定する初期方式と所有

初回は**一つの局所serviceの参加job・保存系を静止させる切替**とする。rolling移行や旧新writer混在で共有Mへ書く方式を採らない。一仕事一確定主体を維持し、Jの制御、Mの承認済み更新、環境BrokerのPermission・消費・receiptを別所有にする。単一writerを全責任の統合と解釈しない。

切替記録はJの版付き制御状態に置く。ownerが採った対象・版・停止・復元条件を封印し、control専用の調整入口から各所有APIへ要求する。調整入口自身が採否・Permission・grantを発行しない。Mや環境Brokerとの別取引を全体ACIDとみなさず、移行ID、expected revision、pending、受領照会を記録する。

既存Approval Gate、L3、brand、監査、Runtime Invariantsを保つ。実切替がinstalled code、設定、policy、service、秘密に触れる場合は、それぞれ既存の必要承認を通す。開発委任やこのADRを本番移行のOwner Approvalへ転用しない。

## 3. 非作用shadowと互換読取

同じ合成済み観測、目的・依存版、比較基準を凍結して候補・採否を比較する。shadowには読取専用射影を渡し、旧新の正本store、live ticket、秘密、Executor、dispatcher、schedule登録、Broker作用経路を渡さない。比較記録は私有の非正本資料へ分離する。通常decideのaudit／memory captureも生産正本へ接続しない。

「read」でも外部送信や資格使用を含み得るため、影実行でlive Providerや外部照会を暗黙に呼ばない。追加取得・計算は別の用途、情報、資源、宛先の承認条件を要する。新旧の採否が一致しても、権限や外部作用の成功を証明しない。

旧recordは元bytes・source版・digest・出所を私有保持し、検査したreaderで非権限の互換射影へ変換する。旧optional field、schema、欠損、壊れた行、未変換残差を明示する。読めない行を黙って捨てず、未知版を自動採用しない。旧payload、memory、history、grantの記録から現在の実行承認を復活させない。全旧recordの実対応はG01.01で確認する。

## 4. 切替のbarrierと照合

各段階は次の段階への実証条件を持つ。途中crash後も通常実行を既定で止め、正本の段階と各所有者のreceiptから照会する。画面やlauncherのsuccessだけで先へ進めない。

| 段階 | ownerと到達条件 | 不成立・結果不明時 |
|---|---|---|
| 準備 | 対象job owner、旧新binary・schema・contract版、J/M revision、writer・起動元、復元点を固定。正確な作用・情報範囲をOwner承認へ結ぶ。 | 対象・版・必要承認が曖昧なら未着手。 |
| 受付凍結 | gateway、CLI、cron、webhook、channel、repair/update、自動起動から新仕事・作用・対象正本更新を止める。独立保護は維持。 | timer停止だけで成立にしない。再起動元や別writerが残れば切替禁止。 |
| 排出・棚卸し | inflight、suspended、approval待ち、grant、消費、worker、M反映待ちを正本・実process・Brokerから確認。保存待ちを完了確認する。 | 停止要求、worker terminal、子孫停止、外部取消は別状態。記録のないpendingはunknownとして保持。 |
| 静止保存 | 対象writerの停止・失効と再起動抑止を確認して整合点T0を採る。全resolved保存先、所有者、版、hash、参照関係、未決作用をmanifestへ記録。 | 稼働中の逐次copyやsourceSpecsだけでconsistent snapshotとしない。欠損・保存失敗は停止継続。 |
| 変換・検査 | 新しい隔離先へ変換し、旧原本を保持。ID／revision／digest／記録件数・参照・chain／消費／unknownを照合する。projectionは正本から再構築。 | 未変換や意味差を無断補完しない。反例は対象契約・試験だけを再開放。 |
| 未決照合 | J pending／M receipt／Broker開始意思・消費・receiptと外部実結果を照合。照合専用read条件だけを用いる。 | ACK不達やspawn前後不明を未実行へ戻さない。非冪等writeを再送せず、照合不能対象を保留・隔離。 |
| writer取得 | 旧writerの実効失効を確認し、新owner・新epoch・expected revisionを確定。保存入口と作用Brokerが古い世代を拒否し、取得結果を照会する。 | leaseファイル・epoch数値だけでは不足。旧writerが世代を理解しない場合はprocess・保存先・作用能力を実際に遮断する。 |
| 検査起動 | 新系を作用禁止で起動し、schema・整合性・現権限・依存・保護・旧結果帰属・receiptを再検査。 | crash後も自動的に旧系へfallbackしない。取得commit不明なら照会し二重取得しない。 |
| 限定再開 | 新しい内容採否、現在Broker Permission、必要Owner Approval、対象、予算、期限、世代を再確認して一系統だけ再開。 | unknown条件では新作用を開始しない。保留jobを成功表示へまとめない。 |

T0 manifestはenvのキー名一覧ではなく、実resolved pathと実体・所属を記録する。audit、旧memory、complete-history、approval、session、failure gate、schedule、設定、秘密参照、新J/M正本、Broker独立台帳の参加・対象外・未観測を区別する。secret値や原典を公開manifestへ載せない。外殻台帳はBLUEのファイルcopyだけで復元できると仮定しない。

epoch／writer取得の実効性は両境界で検査する。保存先だけの排他で外部作用を止めたとせず、Broker失効だけで旧正本書込みを排除したとしない。外部先がfencingや照合を提供しない残差はoutcome_unknownとして表示し、全体exactly-onceを主張しない。

## 5. 戻しの条件

rollbackも新受付を止め、新writer・worker・起動元を停止・失効し、切替後の未決作用とM反映を照合してから行う。新しい記録を消さず、T0以後の開始・消費・receipt・失効を保持する。旧epoch、期限、旧Approval、消費済みticketをbackupから復活させない。

| 復元面 | 成功条件と制限 |
|---|---|
| コード | 正確な旧binary／commit／依存を選ぶ。Gitの二世代はコード・資料の復元点であり、運転状態のbackupではない。 |
| 保存物 | 対象版で検査済みの互換readとwriteを別判定する。旧binaryが読めても新schemaへ書かせない。対応変換がなければ停止を維持。 |
| 消費・現在権限 | T0後の消費・失効・新epochを保持し、環境Brokerに再照会する。古いgrantファイルをcopyしただけで再開しない。 |
| 外部世界 | 受理・取消・実結果を別照合する。DBやファイル復元を外部取消成功へ変換せず、取消不能・補償・不明を明示する。 |

切替前の失敗でも、移行用の失効・消費・停止や部分保存があった範囲を照合する。切替後の戻しでは、非権限の旧読取を可能にしてもwrite能力を自動的に戻さない。旧版へ安全に書戻せない場合は修復または検査済み前進復旧を選び、条件を弱めて起動しない。復帰先も新しい世代を取得し、同じ一系統条件を検証する。

## 7. 非公開差分と利用者への帰還

公開ADRは一般契約、現sourceの不足、採否理由、非対象、受入先を示す。原典・封印詳細・完全対応表・実owner/host・資格・raw履歴・実保存物・内部派生詳細は私有保持する。digest化だけで公開可能にしない。製品配布や外部Cへ原典・作業packet・私有証拠を同梱しない。

利用者へ段階、旧新のwriter、作用禁止・保留の理由、変更済み範囲、未決作用、照会方法、互換write可否、次の安全な操作を示す。PID消失、画面成功、archive存在を切替完了へ置換しない。親B03の各scenarioは資料対応と実試験を分ける。

通常の資料成果は各単位でmainへcommit・push・remote照合する。J0完了・J1未承認、P13 `PENDING_OWNER_GO`、`1.0.0-rc.1`、`public_claim_allowed=false`を維持する。次のC01.01は現在の指示・依存・mode・HEAD・許可pathを新しく確認して開始する。
