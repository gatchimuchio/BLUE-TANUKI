## 変更せず保つ境界と根拠

- `native/rust_helper/src/broker/workspace.rs` 30–57、190–208 の Runtime、root device／file ID、登録 hash の照合を再利用する。登録対応を実アクセス許可・隔離実証へ読み替えない。
- `native/rust_helper/src/broker/protocol.rs` 1770–1778 の認証済み対話 Owner と、2088–2110 の Task 等の native Owner 経路は別用途のままにする。
- `native/rust_helper/src/broker/dialogue.rs` 1664–1707 の開始監査 → 同排他内の grant 消費 → worker の順序を維持する。未監査のまま実行しない。
- `native/rust_helper/src/broker/dialogue.rs` 1882–1941 の本文表示承認、1944–1971 の取消要求、2483–2586 の終端判定を再利用する。要求受領を完了へ変換しない。
- 既存 MethodChannel、PID に結び付いた pipe、認証済み Broker の責任を保つ。Flutter の直接 HTTP、秘密保管、第二の認可経路は追加しない。
- Python の参照 Adapter、履歴・metadata は参照証拠のまま。通常 Release の Task 非対応を schema・設定・表示だけで変更しない。

この再利用判断は、各既存保護の source consumer に根拠がある。接続不足まで「変更不要」としたものではない。

## 後続施工の有限受入

| ケース | 入力・作用 | 実 consumer で観測する期待結果 |
|---|---|---|
| 正常接続 | 固定した BLUE Runtime／Workspace に対し合成要求を1回送信 | 実 Adapter・Broker・BLUE を通る相関付き結果、監査、秘密を含まない表示。宣言だけの成功は拒否。 |
| 結合の否定 | Runtime／Workspace／内容／版の差替、偽発行元、期限切れ、再送、未承認、BLUE 側だけ成立／Broker 側だけ成立 | 現 Permission・必要 Owner 承認と同じ内容で照合し、拒否・監査。hash 一致だけで認証しない。 |
| 障害 | 監査書込み失敗、切断、非対応、版不一致 | 継続や暗黙 fallback をせず、拒否／停止／結果不明を正確に帰還。 |
| 取消・遅延 | 送信前／後の取消、worker 停止前の応答、遅延結果 | 取消要求と実終端を区別。外部作用の結果不明を未実行や成功に置き換えず、照合後に採否。 |

既存の観測可能な試験 selector は `native/rust_helper/src/broker/dialogue.rs` の「AgentTask実行はPermissionとApprovalを再検証して一回消費し出力本文を残さない」「AgentTask結果はOwnerの範囲別Approval後だけ一回取得できAuditへ本文を出さない」「AgentTask取消はworker終了までrunningを保ちterminal監査後だけcancelledとなる」、および `native/rust_helper/tests/agent_task_production_e2e.rs` の `production_agent_task_gate_fails_closed_over_authenticated_ipc`。今回は **NOT_RUN**。将来の接続固有試験をその実 consumer に追加し、fixture・局所実行・導入済み製品・実資格の証拠を分ける。

将来試験の配置も候補ごとに限定する。S01／S02 は新規予定 `native/rust_helper/tests/blue_tanuki_runtime_integration.rs` で実 Adapter・登録・合成端点の相関、認証失敗、版差替、通信断、取消、監査失敗を確認する。S03 は方式確定後、既存 `native/rust_helper/src/broker/dialogue.rs`／`native/rust_helper/src/broker/protocol.rs` の該当試験へ接続する。S04／S05 の表示・取消は既存 `apps/desktop_flutter/test/agent_task_client_test.dart`、対話 consumer を使う場合は既存 `apps/desktop_flutter/test/runtime_dialogue_test.dart` へ接続する。具体的な新 selector は実装前の開始記録へ固定する。これらはすべて未施工・未実行であり、上記の既存 Task 回帰試験だけで BLUE transport を受入しない。

## 独立した接続計画

通常の外部 C 構築は B03 → C01 → C02/C03 → C04 → C05 の依存で進められる。ミニドラ固有の未観測や待機を、この経路全体の一律停止条件にしない。ミニドラ側の実接続は B02.02／B02.04 と C05 の成立後、H01 の専用 consumer で受入する。外部 C の成功をミニドラの成功へ転記しない。

## 復元点と実装前の再同期

BLUE の今回編集前基点は `0869f80f929c4d8e88f03865785641ea0138eb94`。二世代の local recovery branch／remote backup tag は `codex/backup-main` がこの基点、`codex/backup-main-prev` が `8f9881dab5b0b82bceac32714ad01dac72622d22`。

D4 の `8360e90` は提案の source 基点であり、将来の強制 reset 先ではない。実施工直前に双方の最新 HEAD、remote、既存差分の所有者、対象 blob、契約版、保存 schema、未決作用、世代を再固定し、対象 repo の編集前二世代保存を行う。既存の監査、消費済み grant、実行済み外部作用をコード rollback で巻き戻したとしない。互換性のない旧 binary を新しい保存状態へ書き込ませない。

## 成立範囲と未実施

今回の成果は限定提案と公開可能な工程記録。証拠は公開ソース・設定・文書であり、新しい接続の `LIVE_RUNTIME` ではない。外殻変更、BLUE 実 Adapter、Task 昇格、提案試験、installed／live／別 OS 検証、実資格、外部業務作用は未実施。実接続と必要な各 profile の証拠不足は後続の release blocker として保持する。
