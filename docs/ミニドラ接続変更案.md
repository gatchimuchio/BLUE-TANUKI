# B02.04 ミニドラ接続変更案

2026-10-09。公開ソースに基づき、ミニドラ側の最小差分または変更不要となる条件を、BLUE の交換可能な計算装置の契約（C契約）へ結ぶ。今回は資料工程であり、ミニドラの改修・推論・実接続は行っていない。

## 固定版と観測範囲

対象は [NOTNN-LLM-MINIDORA の固定 commit](https://github.com/gatchimuchio/NOTNN-LLM-MINIDORA/commit/c7b87bed3a828bbe83d5741bab89b35fd523a72a)。開始時に GitHub API から repository／main を照合し、B02.02 で取得した同版の archive と一致した。取得済みソースを読み、入口・状態・出力・停止・情報境界と既存試験定義を確認した。全ソースの意味監査、実際の計算・模型状態の同一性、C 適合、性能は証明していない。

既存の package 版 `0.5.0`、API版、`第0層.py` の互換名、仕様参照版は、実際に選択・実行された機構や模型状態の証拠と区別する。

以下の不足はすべて **製品上 OPEN**。今回は各不足の変更先、再利用条件、受入と後継を限定する。

| 不足 | BLUE側で扱う差 | ミニドラ側の限定候補・変更不要条件 | 消費する後継 |
|---|---|---|---|

| MD-G02 実同一性 | package／参照版と実行機構・模型・P状態・依存版を区別し、実観測を要求・結果へ結ぶ。 | 選択実体の `言語確率法則.py:239–244` の状態digest等を取得できれば再利用。観測点が足りない場合だけ、その実体の結果へ識別情報を追加する。`言語基底.py:127–133,224` の定数だけでは足りない。 | C05.01、H01.01 |

HTTP待機終了を計算停止済みと扱わない。既存ブラウザの停止伝達・通信許可は、その能力を選ぶ場合だけ再利用審査し、BLUEのOS隔離の証拠へ転用しない。実入口が決まるまでは、変更不要も実装必要も条件付きの判断とする。

## 後続の有限受入

| 条件 | 正例 | 拒否・保留する負例 |
|---|---|---|
| 入力・出力結合 | 同一要求・射影・版に実結果と根拠が結び付く | request／digest取り違え、不正入力、固定の偽根拠 |
| 実同一性 | 選択した実機構・模型・P状態を観測する | package版や互換名だけを実行証拠にする |
| 採否・状態 | 局所計算の採否・状態範囲を維持し、BLUEが独立して採否する | 局所APPROVEによるBLUE承認代替、無許可の正本更新 |
| 取消・故障 | 実停止・部分結果・不明・遅延を区別し、反映済み作用を記録する | timeoutだけの停止認定、取消後の遅延結果採用、停止判定故障 |
| 情報・作用 | 許可された射影・宛先・保存／表示範囲だけを通す | 無許可読取・送信、保存からの権限昇格、秘密露出 |
| 実証 | 選択した実ミニドラで有限profileを実行する | Fake模型・旧評価値・外部LLM代用 |

既存回帰候補は `tests/test_統合実行.py` の停止故障・構築時／要求時許可、`test_HDS全体運用_実行.py` の保存非昇格・処理中競合、`test_HDS全体運用_製品.py` の会話分離、`test_ブラウザ契約.py` の停止・未許可通信である。実在selectorを照合したが、今回はすべて **NOT_RUN**。新しいC接続固有の試験をこれらで代替しない。実装着手時に選択入口、exact path、入力、観測点、正負selectorを固定する。

通常の外部Cの C05.01→C05.02→C05.03 は独立して進める。ミニドラ固有の H01.01 は B02.02／B02.04／C05.03 に依存する。未取得の旧資料（RS08）に依存する意味採用だけはHOLDを維持し、今回の現物に基づく限定案や一般外部Cを一律停止させない。

## 別repo委任と復元条件

本案件から別repo全面改修の承認を導かない。ミニドラ変更が必要と確認された場合、選択入口・不足・最小path・前後blob・実受入・状態所有・復元条件を固定し、その具体差分への別委任を受ける。保護撤去、無関係refactor、製品名・全言語刷新を含めない。

ミニドラの作業規定に従い、将来の開発・通常検証はsandbox、GitHubの取得・反映はAPI、main一本で扱う。BLUEのbackup branch/tag運用を移植せず、新branchやPRを自動作成しない。反映前に最新mainを再照合し、並行変更があれば再計画する。

復元は変更前commitと対象blobを基準とする。コードの復元、既に更新された局所状態、消費済み許可、監査、外部作用は別に記録する。旧証拠を新版へ無審査で転用しない。

今回のBLUE差分は文書だけで、編集前復元点は `d8f988a9f2d90a37219572873a063b3b86d7fad8`、前世代は `0869f80f929c4d8e88f03865785641ea0138eb94`。私有原典・封印された核心・完全理論対応表・秘密・raw証拠は公開しない。通常の成果保管と製品公開・出荷GOは別判断であり、P13の保留を維持する。
