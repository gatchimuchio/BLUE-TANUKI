# 公開競合能力基準面

この文書は、OpenClaw と Meta Muse の公式公開情報から確認できる能力群を、後続の実装要求と比較条件へつなぐ版付き基準面である。公開元の説明を独立した実動作確認や BLUE-TANUKI の実装・対応・優位性の証拠へ読み替えない。内部 QE 原典や全要求対応表は含めない。

## 未分解で残す動的一覧と公表外情報

- OpenClawのmodel/media provider directory（取得時表示64件）とofficial plugin directory（142件）は、一覧の件数だけ記録し、項目別のAPI/model/permission/price/resource互換はこのsnapshotでは未分解である。後続の要求割当でcatalog全体が必要と判明した場合は、個別ID・参照版・比較条件を追加し、現行snapshotを無言で書き換えない。
- OpenClawのcommunity plugin／skill catalogは継続更新される。未審査packageすべてを同じ能力とみなさず、利用者向け能力とextensionの導入・制御能力を分けて扱う。
- Meta Museは完全なconnector一覧をアプリ内に置くと公表している。記事に記載された接続先以外の個別能力・入出力API・権限scope・料金・resource・移行形式は未確認であり、存在しない／対応しないとは推定しない。
- 両製品のformat、設定・data・skillの移行互換は個別version資料の範囲を越えて推測しない。公開契約が見つからないときは比較要求の未確認条件として残す。

## 共通比較条件

- 各測定には基準面識別子、製品release/build、取得日、OS・architecture、地域、plan、model/provider、拡張一覧、設定、test account scope、入力hash、出力状態を紐付ける。
- 公開元の能力説明は `公表`、実際に操作して観測した結果は `実観測`、資料から確定できない事項は `未確認` とする。公開説明から内部構造や性能を推測しない。
- 料金・resource・permission・再試行条件を記録し、同一にできない比較条件は差として明示する。測定していない結果やchannel数、機能名数を成功・完全包含へ読み替えない。
- 実サービスの送信、購入、公開、実資格の利用はこの基準面では行っていない。今後の比較もownerが明示的に認めたscopeと安全なtest accountに限る。
- A03.03では能力群を実consumer群へ割り当てた。既存の入口・外部操作はF10–F14、未収容の入口・固有serviceはF15.01–.03、extensionはF07–F09、browserはF06、形式・設定移行はF19と該当するOS更新consumerへ送る。目的・権限・継続・記憶・資源にまたがる要求はC/D/E系列と後段のOS/QC consumerへ分ける。
- CB IDごとの詳細割当とservice別子作業指示は、内部QEの全要求対応表をPublic Gitへ転載しない規定に従い、owner管理の非公開作業記録に保持する。この割当は実装・互換・優位性の証拠ではなく、現行v1.0 RCのsupport boundaryを変更しない。未包含能力と動的catalogの残差は維持する。
