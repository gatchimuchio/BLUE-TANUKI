# BLUE-TANUKI 日本語基底語彙

この文書は概念を日本語で成立させ、既存の機械識別子・固有名を参照ラベルとして接続する。英語ラベルから日本語の意味を逆算してはならない。

| 日本語基底語彙 | 参照ラベル | このリポジトリでの意味 |
|---|---|---|
| 判断・権限基盤 | `HDS-BRAIN` | 行為者、過程、記憶、承認、実行の可否を下流より先に決める上流基盤。LLM を判断源として呼ばない。 |
| 人間所有者 | `owner` | 最終責任、明示的 GO、公開判断を保持する人間。テスト成功や LLM 出力から同意を推定しない。 |
| 権限経路 | `authority path` | 入力から判断、承認、実行許可までの経路。外部メタデータ、記憶、完全履歴は権限を昇格できない。 |
| 承認ゲート | `Approval Gate` | リスクと操作を分類し、必要な承認、特に最終レビューを強制する境界。 |
| 承認リスク | `ApprovalRisk` | 承認判断に用いる複数軸のリスク表現。単一の真偽値へ潰さない。 |
| 承認段階 | `ApprovalLevel` | L1 / L2 / L3 と最終レビューを含む承認段階。 |
| 最終レビュー操作 | `final-review operation` | owner の明示的な最終確認なしに実行してはならない操作。別経路で迂回しない。 |
| 監査ハッシュ鎖 | `hash-chain audit` | 監査記録の順序と改変検知を支える連鎖。ログの存在だけを監査完了とみなさない。 |
| 実行時不変条件 | `Runtime Invariants` | 実行中に維持し、証拠として検証する安全条件。 |
| 能力包絡 | `capability envelope` | 下流装置が使用できる能力の明示的上限。外部記述から拡張しない。 |
| 完全履歴 | `complete history` | 再現・監査用の証拠基盤。判断権限には使用しない (`complete_history_used_for_authority=false`)。 |
| 記憶参照 | `F-reference` | 記憶や参照の出所と利用境界。権限根拠へ昇格させない。 |
| 常駐制御面 | `resident control plane` | owner が局所環境で継続操作・確認する制御面。自動的な権限主体ではない。 |
| 第一者面 | `first-party` | BLUE-TANUKI が明示的に支援・検証・責任範囲へ置く面。数の多さで昇格しない。 |
| 先行隔離 | `preview quarantine` | 証拠や安全境界が不足する機能を第一者面から隔離した状態。 |
| 第一層 | `Layer A` | 同梱され、第一者境界で検証される構成。 |
| 第二層 | `Layer B` | 第三者拡張。Plugin Review Gate を通っても HDS 権限は取得しない。 |
| 下流装置 | `downstream device` | LLM、ツール、cron、チャネル、executor など、上流判断に従う実行・投影要素。 |
| 実行器 | `Executor` | 承認済み計画を具体的操作へ移す下流要素。判断基盤を代替しない。 |
| 失敗閉鎖 | `fail-closed` | 不明、矛盾、証拠不足、境界異常のとき許可側へ推定せず停止・保留する性質。 |
| 停止 | `SUSPEND` | 判断または実行を安全側で中断し、再監査へ戻す状態。 |
| 権限不使用証拠 | `used_for_authority=false` | 文書、記憶、外部証拠、LLM 出力が判断権限ではないことを示す境界表現。 |
| 公開主張不許可 | `public_claim_allowed=false` | P13 pre-GO で GA・完全優位などの公開主張を有効化できない状態。 |

## 識別子運用

- コード、API、環境変数、CLI、パッケージ名では互換性のため既存ラベルを維持してよい。
- 日本語文中では、初出時に日本語基底語彙を置き、必要な場合のみ参照ラベルを併記する。
- 同一ラベルが外部で別の意味を持っていても、本リポジトリの意味は本表と関連正本から定まる。
- 新語は日本語で差異・関係・境界を成立させてから、機械識別子を割り当てる。
